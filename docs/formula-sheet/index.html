2. חץ, קו כפול והקרדינליות

חץ מהקשר אל ישות X ← כל מופע של הצד השני קשור ל-X אחד לכל היותר (מקס׳ 1).
קו כפול/עבה בין ישות לקשר ← השתתפות מלאה: כל מופע של הישות משתתף לפחות פעם אחת (מינ׳ 1).
חץ + קו כפול = בדיוק אחד. קו רגיל = 0 או יותר. (a,b)‏ על הקו = בין a ל-b. "יכול" נבדק מול החץ, "חייב" מול הקו הכפול.
  • חץ מהקשר R אל A (בין M ל-A): M בצד ה"רבים", A בצד ה"אחד" ← כל M עם A אחד לכל היותר, A יכול להיות עם הרבה M.
  • ERD לא קושר בין שני קשרים שונים ← "האם ייתכן מצב X?" בין שני קשרים ← לרוב כן.
  • תכונה של הצירוף (ציון של סטודנט בקורס) יושבת על הקשר. קשר בין מופעים של אותה ישות ← רקורסיבי.

3. התרגום היעיל ביותר — מה הופך לטבלה

מהטבלה?מפתח ראשי / היכן נשמר
ישות חזקהכןמפתח הישות; תכונות פשוטות + מורכבות מפורקות
ישות חלשהכן(מפתח הבעלים, מפתח חלקי); הבעלים = FK שהוא חלק מה-PK
קשר 1:N (חץ אחד)לא — ממוזגמפתח צד ה-"1" נכנס כ-FK רגיל (לא חלק מה-PK) לטבלת צד ה-"רבים", עם תכונות הקשר. (טבלה נפרדת עם PK = מפתח צד ה"רבים" — גם מתקבלת)
קשר 1:1לא — ממוזגFK באחד הצדדים; עדיף בצד עם השתתפות מלאה (ואז NOT NULL‏)

מרובת-ערכיםכן(מפתח הישות, הערך)
תת-סוג ISA‏כןמפתח האב (יורש) + התכונות של התת-סוג (הסטנדרט); העתקת תכונות האב גם מתקבלת. אף פעם לא תכונות של אח
  • ספירת טבלאות: ישויות (כולל חלשות ותתי-סוגים) + מרובות-ערכים + קשרי N:M. קשר בינארי 1:N / 1:1 וקשר מזהה ← ממוזגים ואינם נספרים. קשר טרנארי / עם הקבצה ← טבלה משלו גם עם חץ (החץ רק מוציא מפתח מה-PK).
  • השתתפות מלאה ← NOT NULL‏, אבל רק כשהקשר מוזג לטבלת הישות המשתתפת (צד ה"רבים" של 1:N): ה-FK שם NOT NULL‏. השתתפות מלאה בצד ה"אחד" או ב-N:M ← אי-אפשר בלי אילוץ נוסף (trigger / assertion‏).
  • קשר מזהה מול 1:N רגיל: בשניהם המפתח של הצד השני נכנס כ-FK; במזהה הוא חלק מה-PK של החלשה, ברגיל הוא שדה רגיל מחוץ ל-PK.

ERD — דוגמת תרגום

נתון: קשר R3‏ בין M‏ ל-A‏ עם חץ אל A‏ וקו כפול מ-M‏; הקבצה [G–R1–B]‏ כש-R1‏ הוא N:M; קשר R2‏ בין A‏ להקבצה, עם חץ אל A‏.

A(a, …)
M(m, …, a NOT NULL)  -- R3 merged into M; a = FK
R1(g, b)              -- N:M => own table
R2(g, b, a)           -- arrow to A => a not in PK
-- no arrow: R2(g, b, a)  PK = all three
-- arrow => R2 may also merge into R1(g, b, a)

SQL — חלק ב׳

1. השלד וסדר הביצוע

SELECT [DISTINCT] cols, AGG(x)  -- 5
FROM A JOIN B USING(k)          -- 1
WHERE  row_condition            -- 2
GROUP BY cols                   -- 3
HAVING agg_condition            -- 4
ORDER BY x [DESC]               -- 6
  • ✗ אגרגציה ב-WHERE‏ (WHERE credits = MAX(credits)‏, WHERE COUNT(…) > 1‏) — WHERE רץ לפני הקבוצות.
  • ✗ עמודה רגילה ליד אגרגציה בלי GROUP BY: SELECT name, MAX(x) FROM T‏.
  • ✗ אגרגציה מקוננת: AVG(MAX(credits))‏. הפתרון: תת-שאילתה ב-FROM, עם כינוי חובה:
SELECT AVG(maxc) FROM
 (SELECT dept, MAX(credits) AS maxc
  FROM Course GROUP BY dept) AS T
-- without "AS T" => error
  • "לכל X" ← GROUP BY X‏. כל עמודה ב-SELECT שאינה באגרגציה ← חייבת להופיע ב-GROUP BY.
  • קבץ לפי מזהה, לא לפי שם (שני אנשים באותו שם יתמזגו).

2. חיבורים (JOIN)

צורהמחבר לפי
A JOIN B USING(k)‏העמודה k (קיימת בשתיהן באותו שם); מופיעה פעם אחת
A NATURAL JOIN B‏כל העמודות עם שם משותף; אין משותפות ← מכפלה
A JOIN B ON A.x=B.y‏תנאי מפורש — לשמות שונים (dept_id = id‏)
FROM A, B WHERE A.k=B.k‏מכפלה + תנאי. n טבלאות ⇒ n−1 תנאי חיבור
A LEFT JOIN B ON …‏כל שורות A; בלי התאמה ← NULL בעמודות B
  • ✗ FROM Enroll, Course WHERE dept='Math'‏ — אין תנאי חיבור ← כל רישום מוכפל בכל קורס Math; גם AVG יוצא שגוי.
  • שדה מטבלה אחרת (dept‏ כשה-FROM הוא רק Enroll‏) ← עמודה לא קיימת ← שגויה. בדוק לכל עמודה מאיזו טבלה היא באה.
  • שרשרת: הנתון שמסננים לפיו נמצא בטבלה רחוקה ← לצרף את כל הטבלאות שבדרך.
  • עמודות ה-SELECT = בדיוק מה שהשאלה ביקשה ("שם וכותרת" ← name, title‏, לא מזהים).
  • גרסת JOIN יכולה להחזיר כפילויות (שורה לכל התאמה); גרסת IN‏/EXISTS‏ — פעם אחת. אם לא נדרש "ללא כפילויות" — שתיהן נכונות.

3. ספירה ותנאים

  • COUNT(*)‏ שורות · COUNT(c)‏ ערכים לא-NULL (עם כפילויות) · COUNT(DISTINCT c)‏ ערכים שונים.
  • "ביותר מחוג אחד / חוגים שונים" ← GROUP BY id HAVING COUNT(DISTINCT dept) > 1‏ (בלי DISTINCT: שני קורסי Math נספרים 2). אחרי JOIN ל-1:N כל ישות משוכפלת ← לספירת ישויות COUNT(DISTINCT key)‏.
  • "לפחות N" ← >= N‏ · "יותר מ-N" ← > N‏. SUM‏ ≠ COUNT‏.
  • AND‏ קודם ל-OR‏. BETWEEN a AND b‏ כולל קצוות. DESC‏ חל רק על העמודה שלפניו.
  • NULL: השוואה ל-NULL = Unknown ← השורה נזרקת. IS NULL‏ ולא = NULL‏. אגרגציות מתעלמות מ-NULL (פרט ל-COUNT(*)‏).
  • IN‏ ≡ = ANY‏ · NOT IN‏ ≡ <> ALL‏ · UNION‏ מסיר כפילויות (UNION ALL‏ לא) · INTERSECT‏ · EXCEPT‏.

6. "מעולם לא / אין לו" — שלילה

SELECT name FROM Student
WHERE sid NOT IN
  (SELECT sid FROM Enroll
   JOIN Course USING(cid)
   WHERE dept='Physics')
-- ≡ NOT EXISTS (… WHERE e.sid=s.sid)
-- ≡ LEFT JOIN … WHERE x.sid IS NULL
  • תת-השאילתה מחזירה את "הפסולים" (מי שכן עשה), מהטבלה שבאמת מחזיקה את העמודה.
  • ✗ JOIN … WHERE dept <> 'Physics'‏ = מי שנרשם לפחות פעם אחת למשהו אחר (גם אם נרשם גם ל-Physics).
  • ✗ SELECT sid FROM Course‏ — אין עמודה כזו ב-Course.
  • ✗ INNER JOIN … WHERE key IS NULL‏ / INNER JOIN … GROUP BY … HAVING COUNT(*)=0‏ ← תמיד ריק. (מתואם WHERE (SELECT COUNT(*) … )=0‏ — תקין.)
  • NOT IN‏ מול תת-שאילתה שמחזירה NULL ← ריק. "רק X" = כולם − מי שעשה משהו שאינו X.

7. מקסימום / מינימום

WHERE credits >= ALL (SELECT credits FROM Course)  -- ✓
WHERE credits = (SELECT MAX(credits) FROM Course)  -- ✓
WHERE NOT EXISTS (SELECT * FROM Course c2
       WHERE c2.credits > c1.credits)   -- ✓
credits > ALL (SELECT credits FROM Course)‏✗ ריק — אף אחד אינו גדול מעצמו
WHERE credits = MAX(credits)‏✗ אגרגציה ב-WHERE
SELECT MAX(title)‏✗ הכותרת האחרונה באלפבית, לא עם הכי הרבה נק״ז
  • מינימום: <= ALL‏ / MIN‏ / NOT EXISTS … c2.credits < c1.credits‏. >= ALL‏ מחזיר את כל מי שבשיא (תיקו).
  • "הקבוצה עם הכי הרבה" ← GROUP BY g HAVING COUNT(*) >= ALL (SELECT COUNT(*) FROM … GROUP BY g)‏.

8. חילוק — "נרשם לכל ה-X"

"s נרשם לכל קורסי Math" ⟺ "לא קיים קורס Math ש-s לא נרשם אליו" — שלילה כפולה.
SELECT name FROM Student s WHERE NOT EXISTS
 (SELECT cid FROM Course c
  WHERE c.dept='Math'    -- הקבוצה הנדרשת
  AND c.cid NOT IN
    (SELECT e.cid FROM Enroll e
     WHERE e.sid = s.sid))
  • אותו דבר עם NOT EXISTS‏ פנימי: AND NOT EXISTS (SELECT * FROM Enroll e WHERE e.sid=s.sid AND e.cid=c.cid)‏.
  • בספירה: … WHERE dept='Math' GROUP BY sid HAVING COUNT(DISTINCT cid) = (SELECT COUNT(*) FROM Course WHERE dept='Math')‏.
  • ✗ שכחו את dept='Math'‏ בתת-השאילתה החיצונית ← דורש את כל הקורסים מכל החוגים.
  • ✗ JOIN … WHERE dept='Math'‏ / IN (…)‏ = "לפחות קורס Math אחד", לא "כל".
  • חלופה ישנה: (שלו) CONTAINS (הנדרש)‏.
בדיקה של 10 שניות לכל אפשרות: ① כל עמודה קיימת בטבלאות שב-FROM? ② תנאי חיבור לכל טבלה? ③ אגרגציה רק ב-SELECT/HAVING? ④ תת-שאילתה ב-FROM עם כינוי? ⑤ הסינון (dept='…'‏) נמצא במקום הנכון? ⑥ ה-SELECT מחזיר בדיוק את המבוקש?

2. צירוף טבעי — "על מה זה מתחבר?"

רשום את שתי הסכמות והקף כל שם שמופיע בשתיהן. הצירוף דורש שוויון על כולם.
אין שם משותף ← ⊗‏ = ×‏ (מכפלה, בלי שום קישור). שמות שונים לאותו מושג (Emp.dept_id‏ מול Dept.id‏) לא מתחברים ← חייבים σEmp.dept_id = Dept.id(Emp × Dept)‏.
  • שרשרת R ⊗ S ⊗ T‏: T מתחבר עם כל העמודות של תוצאת R ⊗ S‏. כל שם משותף נוסף = עוד אילוץ "אותו ___" (אותו id‏, אותה date‏…) — זה מה שהשאילתה "עושה".
  • מקום ה-σ‏ לא משנה: σc(R ⊗ S) = R ⊗ σc(S)‏ כש-c על עמודות S בלבד. תנאי על עמודה שאינה ביחס ← שאילתה לא חוקית.
  • ×‏ עם n יחסים ⇒ n−1 תנאי חיבור ב-σ‏ (תנאים עסקיים לא נספרים).
  • אין COUNT / SUM / AVG / GROUP BY. "לפחות 2" אפשר (צירוף עצמי עם ≠‏); "בדיוק 1" = הכול − "לפחות 2". ספירה/השוואת כמויות — לא.

3. זהויות — פעולה מורכבת = פעולות בסיס

חילוק R(A,B) ÷ S(B)‏ΠA(R) − ΠA( (ΠA(R) × S) − R )‏
חיתוךR ∩ S = R − (R − S)‏
צירוף טבעיΠ…σR.X=S.X(R × S)‏
הפרש סימטרי(R − S) ∪ (S − R)‏
צירוף חיצוני שמאליR ⋈ S‏ + שורות R בלי התאמה, עם NULL

לזהות חילוק: ΠA(R) × S‏ = כל הזוגות שהיו צריכים להופיע ← פחות R = הזוגות החסרים ← ΠA‏ שלהם = הפסולים ← ΠA(R) −‏ הפסולים = מי שמופיע עם כל S.

4. חילוק — "לכל"

R(x,y) ÷ S(y) = { x | ∀y∈S : (x,y)∈R }

  • Πמי, מה(…) ÷ Πמה(σ…(…))‏. סכמת המחלק מוכלת במחולק; תוצאה = מחולק − מחלק.
  • שם עמודה שונה ← ρ‏ לפני החילוק. ✗ חיתוך במקום חילוק · סדר אופרנדים הפוך.

5. מקסימום / מינימום

מקסימום: Πage(E) − Πf1.ageσf1.age < f2.age(ρf1E × ρf2E)

  • מקרינים את f1 ← מוציאים את מי ש"מפסיד" בתנאי. f1 < f2‏ ← הוצאו כל מי שיש גדול מהם ← נשאר המקסימום. f1 > f2‏ ← נשאר המינימום.
  • ✗ בלי ρ‏ (σE.age<E.age(E × E)‏) ← לא חוקי. ✗ בלי Π(E) −‏ ← מחזיר את כל השאר.

6. חיתוך · הפרש · צירוף עצמי

  • "גם X וגם Y": Πkσc=X(R) ∩ Πkσc=Y(R)‏. ✗ σc=X ∧ c=Y‏ ← ריק תמיד.
  • "מעולם לא": Πk(T) − Πk(T ⊗ R)‏. Πk(T ⊗ R)‏ = "לפחות פעם אחת".
  • "יותר מפעם אחת": ΠR1.kσR1.k=R2.k ∧ R1.a≠R2.a(ρR1R × ρR2R)‏.
  • ספירת שורות: Π‏ ממזג שורות זהות; ⊗‏ על B: לכל ערך של B — (שמאל)×(ימין), וסוכמים.

דוגמה: R(A,B)={(1,x),(2,x),(2,y)}‏, S(B,C)={(x,5),(x,6),(y,7)}‏

  • R ⊗ S‏ (על B): x ← 2×2=4, y ← 1×1=1 ← 5 שורות, 3 עמודות. R × S‏: 9 שורות, 4 עמודות.
  • R ÷ ΠB(S)‏: המחלק {x,y}; רק A=2 מופיע עם שניהם ← שורה אחת, עמודה אחת.

תלויות פונקציונליות — חלק ד׳

1. הגדרות וכללי ארמסטרונג

  • X → Y‏: כל שתי שורות שוות ב-X שוות גם ב-Y. טריוויאלית אם Y ⊆ X‏ (תמיד ב-F+‏). F+‏ = כל מה שנגזר מ-F.
  • רפלקסיביות Y⊆X ⇒ X→Y‏ · הרחבה X→Y ⇒ XW→YW‏ · טרנזיטיביות X→Y, Y→Z ⇒ X→Z‏.
  • איחוד X→Y, X→Z ⇒ X→YZ‏ · פירוק X→YZ ⇒ X→Y‏ · פסאודו-טרנז׳ X→Y, WY→Z ⇒ WX→Z‏.
  • ✗ אין פירוק בצד שמאל: מ-XY→Z‏ לא נובע X→Z‏.

2. סגור X+‏ — הכלי לכל השאלות

1. X+ := X‏ (כולל X עצמו!)  2. לכל Y→Z‏ ב-F: אם Y ⊆ X+‏ ← הוסף Z.  3. חזור עד שסבב שלם לא מוסיף.
X→Y ∈ F+ ⟺ Y ⊆ X+‏ — כך עונים על "איזו תלות נובעת / אינה נובעת".
  • "אינה נובעת": חשב את הסגור של כל צד שמאל באפשרויות; התלות שהצד הימני שלה חורג מהסגור — היא התשובה.
  • תכונה שאף פעם לא בצד שמאל ← הסגור שלה הוא היא עצמה (תלויות ממנה לא נובעות, פרט לטריוויאליות).
  • ✗ מסיחים בשאלת סגור: שכחת את X עצמו · הוספת תכונה דרך תלות שצד שמאל שלה לא כולו בסגור (AC→E‏ כשיש רק C).

3. מפתחות

מפתח-על: X+ = R‏. מפתח קביל: מפתח-על מינימלי — הסרת כל תכונה שוברת אותו. תכונה ראשונית = שייכת למפתח קביל כלשהו.
① תכונה שלא מופיעה בשום צד ימין ← בכל מפתח. ② תכונה רק בצד ימין ← באף מפתח קביל. ③ חשב את הסגור של "הליבה" מ-①; אם = R — זה המפתח היחיד.
  • "מהו מפתח קביל" ← בדוק את האפשרויות: X+=R‏ וגם אף תת-קבוצה לא מספיקה. אם {A}‏ מפתח ← {A,B}‏ הוא מפתח-על בלבד, לא קביל.
  • קרא פעמיים: "קביל" (מינימלי) ≠ "על" (כל מה שמכיל מפתח).
  • מקסימום מפתחות קבילים ב-n תכונות: C(n, ⌊n/2⌋)‏ (מפתח לא מכיל מפתח). n=3 ← 3 (A→B, B→C, C→A‏), n=4 ← 6.

4. תכונה עודפת · כיסוי קנוני Fc‏

  • עודפת בשמאל של XA → Y‏: A עודפת ⟺ Y ⊆ X+‏ (לפי F המלא). קיצור: אם A ∈ X+‏ ← A בוודאות עודפת.
  • עודפת בימין של X → YB‏: B עודפת ⟺ B ∈ X+‏ לפי F′ = (F − {X→YB}) ∪ {X→Y}‏ (כלומר בלי התלות עצמה).
  • תלות עם צד ימין יחיד שאינו נגזר אחרת (A→D‏ כש-D מופיע רק שם) — D לא עודפת. תכונה יחידה בשמאל — אין עודפת בשמאל.
  • Fc‏: פרק צדדים ימניים · הסר עודפות בשמאל · הסר תלויות מיותרות (נגזרות מהשאר) · אחד שמאלים זהים. Fc+ = F+‏.
  • שקילות F ≡ G‏: כל תלות של F נגזרת מ-G וגם להפך (בעזרת סגורים).

5. דוגמה מלאה

R(A,B,C,D,E)‏, F={A→BC, B→D, AB→E, D→C}‏

  • סגורים: A+‏: A → ABC → ABCD → ABCDE. B+={B,C,D}‏. C+={C}‏. D+={C,D}‏.
  • נובע/לא: A→E‏ ✓ · B→C‏ ✓ · C→D‏ ✗ (C+=C‏) · D→B‏ ✗.
  • מפתח: A לא בשום צד ימין ← בכל מפתח; A+=R‏ ← {A}‏ המפתח הקביל היחיד; {A,B}‏ מפתח-על בלבד.
  • עודפות: ב-AB→E‏ ‏B עודפת (B ∈ A+‏). ב-A→BC‏ ‏C עודפת (A→B→D→C גם בלעדיה).
  • Fc = {A→BE, B→D, D→C}‏.

6. מופע (טבלה) מול F

  • שתי שורות שוות ב-X ושונות ב-Y ← X→Y‏ בוודאות לא מתקיימת.
  • המופע מקיים X→Y‏ ← לא מוכיח שהיא ב-F ("ייתכן").

7. צורות נורמליות

צורההתנאי (לכל X→Y‏ לא-טריוויאלית)
1NFערכים אטומיים בלבד
2NFאין תכונה לא-ראשונית שתלויה בחלק ממפתח קביל
3NFX מפתח-על, או כל תכונה ב-Y−X‏ ראשונית
BCNFX מפתח-על. נקודה. (BCNF ⇒ 3NF)
עץ החלטה: ① כל המפתחות הקבילים ② סמן ראשוניות ③ חפש תלות שהשמאל שלה אינו מפתח-על:
אין ← BCNF · בכל ההפרות כל תכונה ב-Y−X‏ ראשונית ← 3NF בלבד · באחת מהן תכונה לא ראשונית ← לא 3NF.
בדוגמה (§5): B→D‏, B לא מפתח-על, D לא ראשוני ← לא 3NF ולא BCNF.

8. פירוק

  • שימור מידע (לשניים): (R1∩R2)+ ⊇ R1‏ או ⊇ R2‏ — החיתוך מפתח-על של אחד הרכיבים.
  • לשלושה רכיבים ומעלה: אחד בהדרגה — R1 עם R2 (בדיקה כנ"ל), התוצאה עם R3…
  • שימור תלויות: כל X→Y‏ יושבת ברכיב אחד (X∪Y ⊆ Ri‏) או נגזרת מההיטלים: res := X‏; חזור על הרכיבים: res ∪= (res ∩ Ri)+ ∩ Ri‏; נשמרת ⟺ Y ⊆ res‏. שני המבחנים בלתי תלויים.
  • BCNF: תלות מפרה α→β‏ ← (α∪β)‏ ו-R−(β−α)‏; חזור. משמר מידע, לא בהכרח תלויות.
  • סינתזת 3NF: Fc‏ ← רכיב לכל תלות; אם אין רכיב עם מפתח — הוסף; מחק רכיב מוכל. משמר גם מידע וגם תלויות.

מודל היחסים — מושגים

  • מפתח-על = קבוצה ייחודית; מפתח קביל = מפתח-על מינימלי; ראשי = הקביל שנבחר. מפתח זר מפנה ל-PK של יחס אחר.
  • שלמות ישות: PK ≠ NULL. שלמות התייחסותית: ערך FK קיים ביחס המופנה, או NULL.
  • הכללה (מלמטה למעלה) / הפרדה (מלמעלה למטה). אילוצי ISA: זר/חופף · מלא/חלקי.

תרגיל חימום לפני חלק ד׳

על F שבשאלה, כתוב בשוליים לפני שקוראים אפשרויות:
① לכל תכונה: מופיעה בשמאל? בימין? ← מי חייב להיות בכל מפתח.
② הסגור של כל צד שמאל ב-F ושל כל תכונה בודדת.
③ מי מהם = R‏ ← המפתחות; המינימליים ← הקבילים.
④ לכל תלות עם שמאל מורכב: האם תכונה אחת בשמאל נמצאת בסגור של השאר? ← עודפת.
עם 4 החישובים האלה עונים על כל 4 השאלות של החלק.

רשימת בדיקה לפני שמסמנים

  1. ERD: חץ = מקס׳ 1 · קו כפול = מינ׳ 1 · 1:N ממוזג לצד ה"רבים" · N:M ← טבלה · PK של קשר = מפתחות הצדדים בלי חץ · השתתפות מלאה בצד ה"רבים" ← NOT NULL‏.
  2. ERD: חלשה ← PK = בעלים + חלקי · מרובת-ערכים ← טבלה · מורכבת ← מתפרקת · מחושבת ← נעלמת · ISA‏ אינו קשר.
  3. SQL: כל עמודה קיימת בטבלה שב-FROM · תנאי חיבור לכל טבלה · אין אגרגציה ב-WHERE ואין אגרגציה מקוננת · כינוי לתת-שאילתה ב-FROM.
  4. SQL: >= ALL‏ ולא > ALL‏ · COUNT(DISTINCT)‏ ל"שונים" · col LIKE '%x%'‏ · "מעולם לא" ← NOT IN‏ ולא <>‏ · "בכל" ← שלילה כפולה עם הסינון בפנים.
  5. אלגברה: הקף שמות משותפים לפני כל ⊗‏ (אין ← מכפלה) · צירוף עצמי דורש ρ‏ · Π(R)−Π(…(Π(R)×S)−R)‏ = חילוק · המוקרן "מפסיד".
  6. תלויות: סגור מתחיל מ-X · לא בשום ימין ← בכל מפתח · מפתח-על ≠ קביל · "אין עודפת" ו"אף אחת" לגיטימיות.
