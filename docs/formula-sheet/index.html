"אף אחת מהתשובות" נכונה ב-13/212 (6%) — אל תפחד לסמן. שלוש הסיבות: עמודה שלא קיימת ביחס · מכפלה קרטזית בלי תנאי חיבור · פרט קטן שחסר בכולן (סגור בלי X עצמו). ב-28 שאלות התקבלה יותר מתשובה אחת — אל תפסול תשובה טובה רק כי מצאת עוד אחת.

SQL — חלק ב׳ (8 שאלות = 40%)

1. סדר הביצוע הלוגי — שורת הזהב

FROM→WHERE→GROUP BY→HAVING→SELECT→ORDER BY

  • ✗ אגרגציה ב-WHERE‏ (WHERE avg(x)>10‏) — WHERE רץ לפני הקבוצות.
  • ✗ תנאי שורה ב-HAVING‏ · HAVING‏ בלי GROUP BY‏ · GROUP BY‏ לפני WHERE‏.
  • ✗ SELECT MAX(x), name FROM T‏ בלי GROUP BY — אגרגציה ליד עמודה רגילה (חזר ב-5 מועדים!).
  • ✗ MAX(COUNT(x))‏ — אין קינון אגרגציות. התחליף: HAVING COUNT(*) >= ALL (SELECT COUNT(*) … GROUP BY …)‏.
  • אגרגציה על אגרגציה ← תת-שאילתה ב-FROM‏ (חייבת alias!) או VIEW: SELECT AVG(p) FROM (SELECT y, MAX(a)-MIN(a) AS p … GROUP BY y) AS Q‏.
  • כלל אצבע: תנאי על שדה שורה ← WHERE. תנאי על COUNT/SUM/AVG ← HAVING.

2. קיבוץ וספירה

SELECT g, COUNT(*)     -- לא-אגרגטיבי ⇒ GROUP BY
FROM A JOIN B USING(k)
WHERE <תנאי שורה>       -- לפני הקיבוץ
GROUP BY g             -- "לכל X" ⇒ GROUP BY X
HAVING COUNT(DISTINCT y) >= 3   -- אחרי הקיבוץ
  • "כמה שונים" / "לפחות N שונים" ← COUNT(DISTINCT c)‏. COUNT(c)‏ סופר הופעות (לא NULL); COUNT(*)‏ סופר שורות.
  • "לפחות N" ← >= N‏ · "יותר מ-N" ← > N‏ · "ייחודי" ← HAVING COUNT(*) = 1‏.
  • קבץ לפי מזהה, לא לפי שם (שני סטודנטים באותו שם יתמזגו — זו תשובה "אף אחת").
  • "נתן" = from_x‏ · "קיבל" = to_x‏ — סמן על הדף מי נותן ומי מקבל.
  • בלי COUNT‏ בכלל ← רשימת שורות, לא צריך GROUP BY. SUM‏ ≠ COUNT‏ ("גובה כולל" = SUM).
  • שנה מתוך תאריך: EXTRACT(YEAR FROM d) = 2024‏ / YEAR(d)‏. "ממוצע לכל X" כש-X מאחורי טבלה שלישית ← ספור טבלאות בשרשרת ובדוק אם יש שתי רמות קיבוץ.

3. מקסימום / מינימום — 3 צורות כשרות

WHERE x >= ALL (SELECT x FROM T)   -- מקסימום
WHERE x <= ALL (SELECT x FROM T)   -- מינימום
WHERE x = (SELECT MAX(x) FROM T)   -- ≡ = ANY (…)
WHERE NOT EXISTS (SELECT * FROM T t2
      WHERE t2.x > t1.x)   -- ⇒ מקסימום
-- t2.x < t1.x ⇒ מינימום
  • "לא קיים גדול ממני" ⇒ מקסימום: הסימן בתת-השאילתה מצביע על מי שנפסל, לא על התשובה. >= ALL‏ מחזיר את כל מי שהגיע למקסימום ("ייתכן יותר מאחד").
  • המגדר/קבוצה עם הממוצע הגבוה: VIEW של הממוצעים + צירוף עצמי AG1.avg > AG2.avg‏, או >= ALL‏.
  • בשאלת "איזה ניסוח מתאים" — ספור את העמודות ב-SELECT; התשובה מכסה את כולן ולא יותר.

4. חילוק — "לכל ה___" (NOT EXISTS כפול)

"X שקשור לכל ה-Y" ⟺ "אין Y שאין לו קשר עם X". המבחן: נסח "…לכל ה-___" עם שם עצם ברבים ← חילוק. אם מתאים רק "אף פעם" ← הפרש (ראה §5).
SELECT s.name FROM Student s
WHERE NOT EXISTS (          -- לא קיים קורס נדרש…
  SELECT * FROM Course c WHERE c.dept='Math'
  AND NOT EXISTS (          -- …שאין לו רישום של s
    SELECT * FROM Enroll e
    WHERE e.sid=s.sid AND e.cid=c.cid))
-- חלופה 1 — הכלה: (שלו) CONTAINS (הנדרש)
WHERE (SELECT cid FROM Enroll WHERE sid=s.sid)
  CONTAINS (SELECT cid FROM Course
            WHERE dept='Math')
-- חלופה 2 — ספירה (אחרי צמצום לקבוצה הנדרשת)
GROUP BY sid HAVING COUNT(DISTINCT cid) =
(SELECT COUNT(*) FROM Course WHERE dept='Math')
  • ⚠ EXISTS‏ פנימי ← "לפחות אחד". NOT EXISTS‏ יחיד ← "אף אחד". רק שלילה כפולה = "לכל".
  • "כולם מקיימים P" ⟺ "אין אחד שמפר את P": WHERE g NOT IN (SELECT g FROM … WHERE NOT P)‏. לא WHERE P‏!
  • המילה "כל" לבד לא מספיקה: "כל פעם לא" = "מעולם לא" = הפרש.
  • בצורת הספירה חובה לצמצם קודם לקבוצה הנדרשת (cid IN (…)‏), אחרת הספירה כוללת קורסים זרים.

5. שלילה — "אין לו / מעולם לא / רק"

x NOT IN (SELECT x FROM R)
NOT EXISTS (SELECT * FROM R WHERE R.x=T.x)
LEFT JOIN R ON R.x=T.x WHERE R.x IS NULL
מסיח קבועלמה שגוי
WHERE col != v‏מחזיר מי שיש לו ערך אחר, לא מי שאין לו v אף פעם
INNER JOIN … WHERE r.x IS NULL‏חיבור פנימי לא מייצר NULL ← תמיד ריק
INNER JOIN … HAVING COUNT(*)=0‏הקבוצה לא נוצרת ← תמיד ריק
LEFT JOIN … WHERE r.col < 60‏תנאי WHERE על הצד הימני הופך ל-INNER (NULL<60 אינו TRUE)
  • "רק X" = הכול − מי שעשה משהו שאינו X. NOT IN‏ ו-NOT EXISTS‏ מתואם שקולים (בלי NULL). NOT IN‏ מול תת-שאילתה שמכילה NULL ← ריק.
  • "רק כיחיד / אך ורק" דורש חיסור — ניסוח בלי שלילה הוא "אף אחת".

6. חיבורים (JOIN)

  • שרשרת מלאה: השדה שמסננים בו בטבלה D ← חייבים לצרף את כל הטבלאות בדרך. ספור טבלאות.
  • פסיק ב-FROM = מכפלה קרטזית ← n טבלאות ⇒ n−1 תנאי חיבור. אחד חסר ← שגוי.
  • בדוק שכל צד ב-ON‏ באמת קיים בטבלה שלו (enrollment_id‏ במקום course_id‏ הוא המסיח השקט). NATURAL JOIN‏ בלי עמודה משותפת = מכפלה.
  • קשר רקורסיבי באורך k (סבתא-אם-נכדה) ← k−1 עותקים של טבלת הקשר, לכל עותק שני תנאים (דור קודם + דור הבא).
  • "יותר מפעם אחת": FROM B b1, B b2 WHERE b1.k=b2.k AND b1.id<>b2.id‏ או GROUP BY k HAVING COUNT(DISTINCT id)>1‏.
  • צירוף שני VIEWs בפסיק ← גם תנאי חיבור (מפתח=מפתח) וגם תנאי התוכן.
  • LEFT JOIN‏ שומר את כל הצד השמאלי; מי שאין לו התאמה מקבל NULL (שימוש תקין: שלילה §5).

7. תנאים · LIKE · NULL · קבוצות

  • LIKE 'x%'‏ מתחיל · '%x'‏ מסתיים · '%x%'‏ מכיל · _‏ תו בודד. =‏ לא מקבל תבניות; '%584%'‏ תופס גם 15847.
  • ספור את התנאים בשאלה = מספר ה-AND‏. AND קודם ל-OR: a AND b OR c‏ = (a AND b) OR c‏. בדוק כיוון (<‏/>‏, =‏/<>‏, השנה).
  • לוגיקה תלת-ערכית: השוואה ל-NULL = Unknown ← השורה נזרקת. IS NULL‏, לא = NULL‏. אגרגציות מתעלמות מ-NULL פרט ל-COUNT(*)‏.
  • IN‏ ≡ = ANY‏ · NOT IN‏ ≡ <> ALL‏ · UNION‏ (מסיר כפילויות; UNION ALL‏ לא) · INTERSECT‏ · EXCEPT‏/MINUS‏.
  • DISTINCT‏ אחרי SELECT מסיר שורות כפולות. BETWEEN a AND b‏ כולל קצוות.
  • ORDER BY: ORDER BY x, y DESC‏ — DESC‏ חל רק על העמודה שלפניו; ברירת מחדל ASC. ORDER BY אינו GROUP BY (שורות חוזרות נשארות).
  • VIEW: INTO V‏ בבחינה ≡ CREATE VIEW V AS‏. סדר העמודות ב-SELECT הוא חלק מהתשובה.
  • DDL: CREATE TABLE T(… PRIMARY KEY(k), FOREIGN KEY(f) REFERENCES S(k), NOT NULL, UNIQUE, CHECK(c))‏ · INSERT INTO‏ · UPDATE … SET … WHERE‏ · DELETE FROM … WHERE‏.

2. קרדינליות והשתתפות — 13 שאלות

חץ אל הישות ← "לכל היותר אחד" (מקסימום 1).   קו כפול/עבה ← "לפחות אחד" (מינימום 1, השתתפות מלאה).
חץ + קו כפול ← "בדיוק אחד". קו רגיל ← 0 או יותר. (a,b)‏ על הקו ← בין a ל-b ((2,2)‏ = בדיוק שניים).
הם בלתי-תלויים: "יכול" נבדק מול החץ · "חייב" נבדק מול הקו הכפול. המסיח הקבוע מחליף ביניהם.
  • חץ מ-X אל Y = רבים-לאחד: כל X קשור ל-Y אחד לכל היותר, אבל בכיוון ההפוך אין הגבלה (ב-Y אחד יכולים להיות הרבה X).
  • ERD לא מבטא אילוץ בין שני קשרים שונים ← "האם ייתכן מצב X?" בין שני קשרים ← כמעט תמיד כן, וזו לא "שגיאה בדיאגרמה".
  • קו עבה חוקי רק בין ישות לקשר; בין ישות לתכונה = שגיאת תחביר. מותר כמה תכונות מרובות-ערכים; אין הגבלה על מספר תת-סוגים.
  • תכונה ששייכת לצירוף של שתי ישויות (ציון של סטודנט בקורס) ← יושבת על הקשר.
  • קשר בין שני מופעים של אותה ישות (חונך) ← רקורסיבי: מעוין המחובר פעמיים, לעולם לא תכונה. ישות שלישית שמוזכרת ← חייבת להופיע.
  • לכפות ייחודיות של (KeyA,KeyB) בטבלת קשר ← חץ מהקשר אל הישות השנייה (לא שני חצים).

  • בדיקת המרת תת-סוג ב-20 שניות: המורכבת התפרקה? המרובה יצאה לטבלה? אין תכונה זרה (של אח/אב)? כל תכונות התת-סוג קיימות?
  • מפתח של קשר: N:M ← שני המפתחות; N:1 ← מפתח צד ה-"רבים" מספיק.
  • IsA — 3 דרכי המרה: (1) טבלה לאב + טבלה לכל תת-סוג עם המפתח בלבד [הסטנדרט במבחן]; (2) טבלה אחת לאב עם כל התכונות (NULL); (3) רק טבלאות לתתי-סוגים שיורשות את תכונות האב — רק אם הכיסוי מלא וזר.

דוגמה מעובדת: עובד(ssn, name, salary) + טלפונים (מרובת-ערכים); מחלקה(dnum, dname); קשר 1:N "עובד ב-" עם חץ אל מחלקה; ישות חלשה Dependent(name, age) של עובד:

Employee(ssn, name, salary, dnum) -- dnum: FK
Department(dnum, dname)
Emp_Phone(ssn, phone)      -- מרובת-ערכים
Dependent(ssn, name, age)  -- חלשה: בעלים + חלקי

4. תיאוריה שחוזרת

  • הפרדה (specialization): מלמעלה למטה, פתוח להוספת תת-סוגים. הכללה (generalization): מלמטה למעלה, רשימה סגורה. אילוצי IsA: זרות/חפיפה (disjoint/overlapping) · כיסוי מלא/חלקי (total/partial).
  • כל ישות חלשה היא נשלטת (תלות קיום: מחיקת הבעלים מוחקת אותה); לא כל נשלטת חלשה. ישות חזקה לא מקבלת את מפתח הישות הקשורה אליה.
  • "קשר חזק" = קשר שאינו מזהה ישות חלשה; IsA לא נספר כקשר.
  • מודל היחסים: מפתח-על (ייחודי) ⊇ מפתח קביל (מינימלי) ∋ מפתח ראשי (נבחר); מפתח זר מפנה ל-PK. שלמות ישות: PK ≠ NULL. שלמות התייחסותית: FK קיים כ-PK ביחס המופנה או NULL. יחס = קבוצה ← אין שורות כפולות ואין סדר; דרגה = #עמודות, עוצמה = #שורות.

  • R ⊗ S = Π…(σR.A=S.A(R × S))‏. אין תכונה משותפת ← ⊗‏ מתנוון ל-×‏. במכפלה שמות העמודות חייבים להיות שונים — אחרת ρ‏.
  • n יחסים ב-×‏ ⇒ בדיוק n−1 תנאי חיבור ב-σ‏. ספור שוויונות בין טבלאות; תנאי עסקיים (city='…'‏) לא נספרים.
  • ⊗‏ מזווג לפי כל השמות המשותפים — רשום את שתי הסכמות, הקף כל שם שחוזר, ספור. מסיח: ניסוח שמוותר על אחת מהן.
  • אין COUNT / SUM / AVG / GROUP BY. "יותר מאחד" ניתן לביטוי (צירוף עצמי); "בדיוק כמה" — לא.
  • לפני סמנטיקה בדוק חוקיות: כל עמודה ב-Π‏/σ‏ קיימת ביחס? (4 שאלות "אף אחת" מהסיבה הזו).

2. חילוק — "לכל"

R(x, y) ÷ S(y) = { x | ∀y∈S : (x,y)∈R }

  • x = מי (התוצאה), y = את מה (הקבוצה שצריך לכסות): Πwho,what(…) ÷ Πwhat(σ…(S))‏.
  • סכמת המחלק מוכלת בסכמת המחולק; המחולק חייב ≥2 תכונות — מחולק יחיד ← פסול מיד. תוצאה = מחולק − מחלק.
  • שם עמודה שונה (id‏ מול student_id‏) ← חובה ρ‏, וזה נספר כפעולה ("חילוק + שינוי שם" = 2).
  • מסיחים: חיתוך במקום חילוק ("גם וגם" של שניים, לא "לכל"); סדר אופרנדים הפוך.

3. מינימום / מקסימום — הפרש + צירוף עצמי

Πid(T) − ΠT1.id σT1.x > T2.x(ρT1T × ρT2T)  = מינימום

  • "כל המזהים פחות מי שקיים קטן ממנו". הכינוי שמקרינים הוא זה ש"מפסיד" בתנאי: מקרינים T1 ו-T1.x > T2.x‏ ← הגדולים מוצאים ← נשאר מינימום. הופכים סימן (או כינוי) ← מקסימום. ההתחלה תמיד Πid(T) −‏.
TRes ← σT1.g>T2.g(ρT1T × ρT2T)‏כל הזוגות (גדול, קטן)
ΠT1.g(TRes)‏  /  ΠT2.g(TRes)‏הכול פרט למינימום / הכול פרט למקסימום
TR1 ← ΠT1.g(TRes) ∩ ΠT2.g(TRes)‏האמצעיים (יש מתחת וגם מעל)
Πg(T) − TR1‏המינימום וגם המקסימום

4. צירוף עצמי · חיתוך · הפרש

  • "יותר מפעם אחת": ΠR1.k σR1.k=R2.k ∧ R1.a≠R2.a(ρR1R × ρR2R)‏. בלי הפרש אי-אפשר לבטא "אך ורק" / "לכל".
  • "גם X וגם Y" (בשתי שורות): Πnσc=X(R) ∩ Πnσc=Y(R)‏.   ✗ σc=X ∧ c=Y‏ = ∅‏ תמיד (שורה אחת לא מחזיקה שני ערכים). איחוד = "או".
  • "מעולם לא / אין לו / רק": Πk(T) − Πk(T ⊗ R)‏. הפוך סדר ← ריק; איחוד במקום הפרש ← מחזיר הכול.
  • Πk(T ⊗ R)‏ = "לפחות אחד" (רק מי שיש לו שורה ב-R).

5. חישוב שורות ועמודות

  • קודם Π‏ — אחד שורות זהות. צירוף טבעי על עמודה משותפת B: לכל ערך של B, (שורות משמאל)×(שורות מימין), וסוכמים. עמודות = |R|+|S|−|משותפות| (B פעם אחת; ב-×‏ פעמיים). ואז σ‏ מסנן.
  • ÷‏: עמודות = מחולק − מחלק; שורה x נכנסת אם היא מופיעה עם כל ערכי המחלק.

דוגמה (אותם יחסים ב-25B וב-25C):

R(A,B,C) = {(2,2,3) (1,2,5) (3,2,7) (2,5,3) (2,2,5)}
S(A,B,C) = {(1,5,7) (1,2,5) (3,6,5) (3,2,3) (2,2,2)}
  • σA≤2(ΠA,B(R) ⊗ ΠB,C(S))‏: ΠA,B(R)‏ = 4 שורות (לא 5 — (2,2) התמזגה), ΠB,C(S)‏ = 5. צירוף על B: B=2 ← 3×3=9, B=5 ← 1×1=1 ← 10 שורות × 3 עמודות (A,B,C). אחרי σA≤2‏: 2×3+1 = 7 שורות, 3 עמודות.
  • ΠA,B(R) ÷ ΠA(S)‏: מחלק {1,2,3}; סכמת התוצאה {B}; B=2 מופיע עם 1,2,3 ✓, B=5 רק עם 2 ✗ ← שורה אחת, עמודה אחת.

תלויות ונרמול — חלק ד׳ (4 שאלות)

1. תלות פונקציונלית וכללי היסק

  • X → Y‏: לכל שתי שורות שמסכימות על X — מסכימות על Y. טריוויאלית אם Y ⊆ X‏. F+‏ = כל התלויות הנגזרות מ-F.
  • ארמסטרונג (נאותים ושלמים): רפלקסיביות Y⊆X ⇒ X→Y‏ · הרחבה X→Y ⇒ WX→WY‏ · טרנזיטיביות X→Y, Y→Z ⇒ X→Z‏.
  • נגזרים: איחוד X→Y, X→Z ⇒ X→YZ‏ · פירוק X→YZ ⇒ X→Y, X→Z‏ · פסאודו-טרנזיטיביות X→Y, WY→Z ⇒ WX→Z‏.
  • ✗ אין פירוק בצד שמאל: מ-XY→Z‏ לא נובע X→Z‏.

2. סגור תכונות X⁺ — הפרוצדורה שהכול בנוי עליה

1. X+ := X‏ — מתחילים מ-X עצמו (הטעות מספר 1: סגור בלי A עצמו ← "אף אחת").   2. חזור: לכל Y→Z‏ ב-F, אם Y ⊆ X+‏ הוסף Z.   3. עצור כשסבב שלם לא הוסיף כלום.
X→Y ∈ F+‏ ⟺ Y ⊆ X+‏. אל "תוכיח" עם ארמסטרונג — חשב סגור.
  • תכונה שאף פעם לא בצד שמאל ← הסגור שלה = היא עצמה ← תלות ממנה "אינה ב-F⁺" (המסיח/התשובה הקבועים).
  • "אילו תלויות בסגור" — חשב X⁺ של כל צד שמאל שבאפשרויות ובדוק הכלה; אל תעצור אחרי שמצאת אחת ("יותר מאחת" תשובה נפוצה).
  • דוגמה חוזרת (25B/25C): F={A→B, C→BD, E→B, AB→E}‏: A+=ABE‏, C+=CBD‏, B+=B‏, (AC)+=R‏ ← מפתח קביל {AC}‏; B→E ∉ F+‏.

3. מפתחות

מפתח-על: X+ = R‏.   מפתח קביל: מפתח-על מינימלי (הסר כל תכונה — נשבר). כל קביל הוא על; לא כל על הוא קביל. ראשוני (prime) = תכונה באיזשהו מפתח קביל.
① תכונה שמופיעה רק בצד שמאל או בשום צד ← בכל מפתח.   ② תכונה רק בצד ימין ← באף מפתח.   ③ "מי מהבאים מפתח" ← בדוק את האפשרויות, אל תחפש מאפס.
  • קרא את המילה "קביל" / "על" פעמיים: אותם נתונים (C→AEF‏, C רק בשמאל, C+=R‏) ← {ABC},{BC},{CD}‏ כולם מפתחות-על אבל אף אחד לא קביל (רק {C}‏).
  • R(A,B,C)‏: מקסימום מפתחות קבילים = 3 (A→B, B→C, C→A‏). F={C→B, B→A}‏ ← C לא בימין, C+=R‏ ← מפתח קביל יחיד.

4. תכונה עודפת (extraneous)

  • בצד שמאל של XA → Y‏: A עודפת אם Y ⊆ X+‏ (סגור לפי כל F) — התלות מתקיימת גם בלי A. תבנית: "X→…A…‏ ואז XA→W‏" ← A עודפת תמיד.
  • בצד ימין של X → YB‏: B עודפת אם X→B‏ נגזרת בלי התלות הזו (חשב X+‏ לפי (F − {X→YB}) ∪ {X→Y}‏).
  • תלות עם תכונה יחידה בשמאל — אין בה עודפת בשמאל. "אין תכונה עודפת" היא תשובה לגיטימית. בדוק שני הצדדים.

5. כיסוי מינימלי (קנוני) Fc

  • תנאים: (1) Fc+ = F+‏; (2) אין תכונות עודפות; (3) אין שתי תלויות עם אותו צד שמאל (אוחדו) / צד ימין יחיד; (4) אין תלות מיותרת.
  • אלגוריתם: Fc := F‏; חזור { אחד α→β, α→γ‏ ל-α→βγ‏; הסר תכונות עודפות } עד שאין שינוי.
  • שקילות F+=G+‏: לכל X→Y‏ ב-F בדוק Y ⊆ X+G‏, וגם בכיוון ההפוך. הכלה סינטקטית לא נדרשת.
  • להוכיח ש-F2 כיסוי מינימלי של F1: F1+ = F2+‏ + ב-F2 אין עודפות/מיותרות. המינימליות נבדקת על F2, לא על F1.

6. מופע חוקי מול F

  • המופע מפר X→Y‏ (שתי שורות שוות ב-X, שונות ב-Y) ⇒ X→Y ∉ F‏ — ודאי.
  • המופע מקיים X→Y‏ ⇒ לא נובע שהיא ב-F (מופע עתידי עלול להפר). בשני הכיוונים התשובה "ייתכן".

7. דוגמה מלאה — פירוק BCNF מול סינתזת 3NF (אלגוריתמים ב-§10)

R(A,B,C,D)‏, F={AB→CD, C→B}‏. מפתחות: AB‏, AC‏ (ראשוניים A,B,C). C→B‏: C לא מפתח-על, B ראשוני ← 3NF, לא BCNF.

  • פירוק BCNF לפי C→B‏: R1(C,B)‏, R2(A,C,D)‏. חיתוך {C}, C→B‏ ← משמר מידע ✓. AB→CD‏ לא יושבת באף רכיב ולא נגזרת מ-{C→B, AC→D}‏ ← לא משמר תלויות.
  • סינתזת 3NF: Fc={AB→CD, C→B}‏ ← רכיבים (A,B,C,D)‏, (C,B)‏; השני מוכל בראשון ← נמחק; הראשון מכיל מפתח ← התוצאה R‏ עצמו: 3NF, משמר מידע ותלויות.

סגור ומפתח: F={A→BC, E→CF, B→E, CD→EF}‏ על R(A,…,F)‏: (AD)+‏ = AD → ABCD → ABCDE → ABCDEF = R; A+=ABCEF‏, D+=D‏ ← AD מפתח קביל (D לא בשום צד ימין ← בכל מפתח).

8. צורות נורמליות

צורההתנאי (לכל X→Y‏ לא-טריוויאלית ב-F⁺)
1NFכל הערכים אטומיים (אין מרובות-ערכים/מורכבות בתא)
2NF1NF + אין תלות חלקית של תכונה לא-ראשונית בחלק ממפתח קביל
3NFX מפתח-על, או כל תכונה ב-Y−X‏ היא ראשונית
BCNFX מפתח-על. נקודה.   BCNF ⇒ 3NF, לא להפך
עץ ההחלטה: ① מצא כל המפתחות הקבילים ② סמן תכונות ראשוניות ③ חפש תלות שצד שמאל שלה אינו מפתח-על:
לא מצאת ← BCNF (וגם 3NF) · מצאת וצד ימין ראשוני ← 3NF בלבד · צד ימין לא-ראשוני ← לא 3NF ולא BCNF.
  • הסימן המזהה ל-"3NF בלבד": 4 תכונות, שני מפתחות שחולקים תכונה, תלות אחת מצד ראשוני (AB→CD, C→B‏; AB→C, AB→D, C→A‏).
  • אל תבחר "לא 3NF ולא BCNF" רק כי מצאת הפרה — בדוק ראשוניות הצד הימני. (A→BC, AE→D‏: מפתח AE, B,C לא ראשוניים ← לא ולא.)
  • כל רכיב של פירוק BCNF הוא גם 3NF. "R לא ב-BCNF, והפירוק ב-3NF" — תשובה לגיטימית.

9. פירוק — שני המבחנים

שימור מידע (lossless, פירוק לשניים): R1∩R2 → R1‏ או R1∩R2 → R2‏ ב-F⁺ — החיתוך הוא מפתח-על של אחד הרכיבים. פרוצדורה: I := R1∩R2‏, חשב I+‏, בדוק I+ ⊇ R1‏ או ⊇ R2‏.
שימור תלויות: (F1 ∪ … ∪ Fn)+ = F+‏ (Fi‏ = היטל F על Ri‏). בדיקה מהירה: לכל X→Y‏ — יש רכיב שמכיל את X∪Y‏? אין, ולא נגזרת מההיטלים ← לא משמר.
  • בדיקת תלות מול היטלים: res := X‏; חזור לכל Ri‏: res := res ∪ ((res ∩ Ri)+ ∩ Ri)‏; אם Y ⊆ res‏ — נשמרת.
  • "מפסיד מידע" לא גורר "מפסיד תלויות" — בדוק בנפרד. ארבע תוצאות אפשריות וכולן הופיעו: לא ולא · תלויות בלבד · מידע בלבד · שניהם.
  • פירוק לשלושה ויותר: בדוק זוגות בהדרגה (R1‏ עם R2‏, התוצאה עם R3‏).

10. אלגוריתמי הפירוק והשוואה

  • פירוק ל-BCNF: כל עוד יש Ri‏ לא ב-BCNF: מצא α→β‏ מפרה (α‏ לא מפתח-על של Ri‏), החלף את Ri‏ ב-(α ∪ β)‏ ו-(Ri − β)‏. סדר הבחירה משפיע על התוצאה.
  • סינתזה ל-3NF: חשב Fc‏; לכל α→β‏ ב-Fc‏ צור Ri = αβ‏; אם אף רכיב לא מכיל מפתח קביל — הוסף רכיב עם מפתח; מחק רכיב המוכל באחר.
שימור מידעשימור תלויותכפילויות
3NF (סינתזה)תמידתמידייתכנו (מתיר הפרה מצד ראשוני)
BCNFתמידלא בהכרחאין

זו הסיבה שבפועל מסתפקים ב-3NF. דוגמה: R(A,B,C)‏, F={AB→C, C→B}‏, מפתחות AB, AC; פירוק BCNF לפי C→B‏: (C,B),(A,C)‏ מאבד את AB→C‏.

NoSQL — חלק ה׳ (לא הופיע מ-2024)

  • יוצא דופן: AWS‏ · Azure‏ · GCP‏ = ספקי ענן; NoSQL = סוג בסיס נתונים.
  • מובנה, טבלאי, עסקאות מורכבות, כסף/הימורים/הוצאות ← SQL. לא-מובנה, בלי סכמה, טקסט חופשי, המלצות, רשת חברתית ("חברים של חברים"), נפח עצום/זמן אמת ← NoSQL.
  • ✗ "NoSQL לא משתמש ב-SQL בכלל" · "תמיד טבלאי" · "מחליף את SQL בכל המקרים" — NoSQL משלים, לא מחייב סכמה, ויש בו שפות דמויות-SQL.
  • MongoDB: db.users.find({ "age": { $gt: 30 } })‏ — שני זוגות סוגריים, בלי >‏. $gt $gte $lt $lte‏; $or: [ {…}, {…} ]‏ = "או"; find‏ = אחזור בלבד (לא עדכון/מחיקה). אגרגציה (_id‏ = GROUP BY, $multiply‏ מקבל מערך):
{ $group: { _id: "$item",
   total: { $sum: { $multiply:
             ["$price","$quantity"] } } } }
  • Neo4j → מסד גרפי → שפת Cypher → traversal עמוק; לא לנתונים רלציוניים.
  • CAP = Consistency · Availability · Partition tolerance — אי-אפשר את שלושתן; רק CAP עוסק בפשרת הזמינות. ACID = תכונות טרנזקציה (Atomicity, Consistency, Isolation, Durability). BASE = גישת NoSQL.
  • Sharding מחלק (כל רסיס במקום אחד) ← לא משכפל. Replication / גיבוי / ייצוא ← משכפלים.

12 בדיקות של שתי שניות לפני שמסמנים

  1. ספור תנאים בשאלה = מספר ה-AND‏; בדוק כיוון של כל אי-שוויון ואת השנה/הערך.
  2. אגרגציה ב-WHERE · HAVING בלי GROUP BY · MAX(x), name‏ · MAX(COUNT)‏ ← פסול מיד.
  3. פסיק ב-FROM או ×‏: n טבלאות ⇒ n−1 תנאי חיבור; כל ON/Π‏/σ‏ מפנה לעמודה שקיימת.
  4. "לכל ה___" ⇒ שלילה כפולה / ÷‏ עם מחולק זוג / (שלו) CONTAINS‏ (הנדרש). "כל פעם לא" ⇒ הפרש.
  5. "מעולם לא / אין / רק" ⇒ NOT IN‏ · NOT EXISTS‏ · LEFT JOIN + IS NULL‏ · −‏. לא !=‏, לא INNER + IS NULL‏.
  6. מקסימום: >= ALL‏ · = (SELECT MAX)‏ · NOT EXISTS‏ (גדול ממני). באלגברה: המוקרן "מפסיד".
  7. "גם וגם" בשתי שורות ⇒ חיתוך (σc=a∧c=b‏ = ריק). "יותר מפעם אחת" ⇒ צירוף עצמי עם ≠.
  8. חץ = מקסימום 1 · קו כפול = מינימום 1 · "יכול" מול חץ, "חייב" מול קו כפול · IsA אינו קשר.
  9. המרה: מרובת-ערכים ⇒ טבלה · מורכבת ⇒ מתפרקת · מחושבת ⇒ נעלמת · N:M ⇒ טבלה · חץ ⇒ FK · תת-סוג ⇒ מפתח יורש + תכונותיו.
  10. X+‏ מתחיל מ-X · תכונה שאף פעם לא בימין ⇒ בכל מפתח · "קביל" (מינימלי) ≠ "על" · "אין עודפת" לגיטימי.
  11. מצאת הפרה ⇒ בדוק אם צד ימין ראשוני: כן ⇒ 3NF בלבד; לא ⇒ לא 3NF ולא BCNF.
